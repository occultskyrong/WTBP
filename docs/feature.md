# Feature 待办清单

本清单是 WTBP 下一步工作的唯一待办入口，用于记录已经确认、但尚未完成的 Feature、修复、治理和文档任务。
它不替代 Issue：需要讨论、协作或可追溯外部决策时，再为对应事项创建 Issue。

## 使用规则

- 每个事项只描述一个可交付目标，并使用稳定的 `F-xxx` 编号。
- 新增事项时必须填写优先级、验收条件和下一步动作；依赖不明确时标记为“待确认”。
- 任务开始后更新状态；完成后保留在“已完成”区域一个版本周期，再归档或移除。
- 不记录密钥、个人信息、完整日志或尚未确认的实现细节。

## 状态与优先级

| 状态 | 含义 |
|---|---|
| 待确认 | 需求尚未确认，不能开始实施 |
| 待开始 | 目标与验收条件明确，可以排期 |
| 进行中 | 正在实施或验证 |
| 受阻 | 缺少依赖、权限或决策 |
| 已完成 | 已满足验收条件 |
| 已取消 | 不再实施，保留原因 |

`P0` 表示阻断或高风险事项，`P1` 表示近期重要事项，`P2` 表示可排期优化事项。
