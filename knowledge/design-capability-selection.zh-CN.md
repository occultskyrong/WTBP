# 设计能力选择记录

在检查官方 Figma 能力、建立项目契约、修改 Figma、实现代码或执行验收之前使用本记录。它把能力发现沉淀为一份小而可复核的决策；它不是新的执行 Skill，也不能替代项目设计契约（`PDC`）或后续任何门禁。

## 必填记录

每个实质不同的设计任务都创建或刷新 `DCS-YYYYMMDD-VNN`，记录以下内容：

1. **任务边界**：目标结果、已声明 target/终端、所处阶段、Figma 与仓库范围、所需读写授权，以及完成所需证据。
2. **本地优先结果**：`wtbp "<任务>"` 的结果、选中的本地 Skill、排除的候选，以及采用 `direct-use`、`adapt`、`compose`、`reference-only` 或 `build-local` 的原因。
3. **已收录外部能力决策**：相关外部能力卡 ID、来源/版本/状态、允许的采用方式及该能力可证明的内容。外部能力卡不构成安装或执行授权。
4. **条件分支**：是否需要视觉方向、Icon 设计、动效设计、Code Connect 或经明确授权的第三方审计，以及对应的责任方与交接条件。
5. **兜底与收录**：只有本地 Skill 和已登记外部能力卡都不存在明确适配时，才使用 `external-capability-discovery`。用户说出 `wtbp，收集 <公开 URL>` 时，使用 `external-capability-curation`；记录产出的未安装能力卡及场景/Case，而不能把收录当作采用。
6. **授权边界**：官方 Figma 能力可用性仍单独记录为 `EX-01`。未经单独用户授权以及 `EX-03`/`EX-04` 边界，不得安装、鉴权、执行第三方能力，或声称其结果。

## 选择矩阵

| 需要解决的问题 | 默认本地责任方 | DCS 决策 |
|---|---|---|
| 从需求创建可编辑设计 | `prd-to-figma` | 选择创建流程；架构和 Figma 写入前必须完成 PDC。 |
| 修改有范围的既有 Figma 设计 | `figma-evolve` | 选择 `patch` 或经明确授权的 `regenerate`，保留原基线。 |
| 将 Figma 实现到一个产品终端 | `figma-to-product` | 只选择一个 target，并映射到项目契约和页面规格。 |
| 比对 Figma 与运行中终端 | `figma-verify` | 选择 target/视口/状态矩阵；不得只凭截图验收。 |
| 确立视觉方向 | `visual-direction` | 在页面样式前运行；任何 Figma 写入前均须人工确认。 |
| 新建或扩展缺失的 Icon 家族 | `icon-design` | 只针对已批准范围运行；回写 `ICON` 清单，不能成为页面局部替代物。 |
| 定义动效行为 | `motion-design` | 仅行为需要动效证据时运行；它不授权 Figma 或代码写入。 |
| 把可复用 Figma 组件映射到代码 | `figma:figma-code-connect` | 项目和组件复用边界明确后使用，并记录 `EX-02`。 |

## 失败即阻断规则

- 不得只因关键词命中就进入 Figma 流程；必须先记录本地优先决策和任务边界。
- 在线发现的候选只是临时证据，不能因此安装、执行或写入登记表。
- 收录的 URL 默认只是未安装、可搜索的参考能力卡，不是已选方案。
- 没有明确能力匹配时，报告 `no_match` 或 `Unverified`，说明缺失证据，并在修改 Figma 或代码前停止。
- DCS 只选择流程；`PDC`、`ARC`、`INV`、`PS`、`AGC`、`ICON`、`BF`、`G` 和验收门禁仍决定产物能否继续或完成。

## 最小交接内容

每次 Figma 流程交接必须包含 DCS ID、选定的本地责任方、采用方式、查阅的外部能力卡 ID（或 `none`）、条件分支决策、官方能力状态，以及所有 `Unverified` 或阻断边界。将 DCS 链接到后续的 PDC、设计批次、实现记录或验收记录。
