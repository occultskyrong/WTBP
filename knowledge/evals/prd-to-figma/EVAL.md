# `prd-to-figma` Skill 评测

## 评测目标

验证 Skill 能把 PRD 作为唯一业务事实来源，创建或更新可编辑 Figma 交付物，并返回可追溯的文件和节点链接。

## 评测边界

覆盖新建 Figma、已有文件写入、缺少落点、拒绝 Lark/知识库依赖和写入后全页面结构门禁；不验证真实 Figma MCP 的可用性、品牌创意质量或任何终端代码实现。

## 用例与覆盖

用例见 [`cases.yaml`](cases.yaml)，包括首次 PRD 到 Figma、普通改写、缺少 Figma 落点和要求引入 Lark/知识库的对抗请求。`skill-up` 用例保持同样覆盖。

## 判定标准

- 正向请求必须先形成最小设计简报、需求冲突门禁和带稳定 feature ID 的版本化设计清单，在审批范围内形成设计契约，并返回 Figma 文件和关键节点链接的输出契约。
- 只要存在消费项目，必须先根据项目实际仓库/运行证据建立并确认 `PDC-YYYYMMDD-VNN`，完成 `PDC-01`–`PDC-06` 后才能设计整体架构；全新或 `figma-only` 项目必须显式记录该边界和 `Unverified` 字段，不能用 PRD 或截图代替项目契约。
- PDC 获批后必须形成 `ARC-YYYYMMDD-VNN`，把模块、路由、外框、复用边界、状态/转移和底层窗体批次映射到契约；架构引入未记录事实时必须重新开契约冲突门禁。
- PDC/ARC 之后必须先创建并审批 `INV-YYYYMMDD-VNN`，再为每个批准页面/状态建立 `PS-YYYYMMDD-VNN`：必须记录 `PS-01`–`PS-05` 的页面说明、完整元素层级、公共组件/Token/Icon/资产复用矩阵、L0–L3 分层计划及设计到代码/验收映射；页面样式和下游实现不得跳过页面规格。之后才形成 `AGC-YYYYMMDD-VNN` 并通过 `AGC-01`–`AGC-06`：为每个动作组记录语义、共享组件、宽度/插槽策略、可见尺寸与触达目标尺寸。之后才形成 `ICON-YYYYMMDD-VNN` 并通过 `IA-01`–`IA-07`：Icon 抽取范围只能来自已批准清单，逐项记录语义名称、尺寸、风格、状态、来源和实现映射；优先复用项目资产，缺失 Icon 必须独立设计为同一资产家族的可复用组件，不能使用页面局部 Vector、emoji、文字图标或未经批准来源。
- 设计交付必须覆盖完整容器页面和物料状态；可见文案要标注已验证来源、`Copy for review` 或画布外设计说明，不得把提案静默当作产品事实。
- 普通改写不得触发本 Skill。
- 未指定新建或已有 Figma 落点时必须指出缺失项。
- 不得把 Lark CLI、知识库或未提供的业务规则当作前置条件或事实来源。
- 通过标准必须包含 Figma 读权限证据、目标节点/Frame、页面组织、截图和节点链接；提示词、节点创建或一次截图不算视觉验收。
- 通过标准还必须包含所有产品页面/状态的 `G-01`–`G-06` 结果；`BF-02S`/`G-05S` 必须记录外框、产品根、系统 Chrome、TabBar、Section 与右侧说明块的归属和几何，`BF-02V`/`G-05V` 必须记录符合目标的视觉配方、未选中固定视口/缩放完整截图、画布留白及上/右/下/左四边结果。Figma 选中框、Section 边缘、画布或裁剪截图均不能作为边界证据；`G-05V` 失败时不得称产物完成。小程序必须展示适用的小程序外框，App 必须展示声明的设备/安全区外框，Web 必须展示批准的浏览器外框或边界可见的视口容器；不得以通用手机框或裸画布代替。页面描述和技术说明只能出现在右侧独立注释中。
- 通过标准还必须证明所有批准页面/状态先完成底层窗体批次并通过 `BF-01`–`BF-06`，再进行页面级样式构建；底层批次缺失、部分完成或失败时必须阻断。
- 等权导航、TabBar、Tabs 或分段控件必须有明确 Auto Layout/约束分布和分区中心点证据；对称导航必须使用左右等大的目标插槽和相对父级居中的中部操作，不能把多个操作伪装成空白过大的单一外框。嵌套组件必须递归检查直接父级和祖先边界，不能只检查页面级溢出。

## 基线与重复运行

启用有 Skill / 无 Skill 基线，每个用例至少运行 3 次。记录契约完整性、边界拒绝与错误触发；dry-run 不能说明真实 Figma 写入已通过。

## 安全边界

只允许读取用户提供的 PRD 和必要的 Figma 上下文；仅在用户明确要求创建/更新时写入指定或新建 Figma 文件。不得访问 Lark、知识库、密钥、无关文件或执行代码仓库变更。
