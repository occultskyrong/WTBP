# 接口四层测试体系与发布门禁

## 问题定义

单独使用单元测试、Mock 测试或接口冒烟测试，都无法同时证明接口已部署、真实请求可用、逻辑分支完整和业务链路闭环。需要用同一份接口契约和测试数据边界组织四层证据。

## 适用场景

- 后端 HTTP/JSON API，需要区分部署故障、契约漂移、逻辑缺陷和业务链路缺陷。
- 需要覆盖可用性探针、真实主流程、Mock 异常分支和多接口 CRUD 链。
- 需要把测试接入 Pull Request、部署后验收和夜间回归。

## 不适用场景

- 只有一次性手工调用、没有稳定接口契约的临时调试。
- 把生产写操作当作集成测试数据准备方式。
- 仅靠代码覆盖率推断接口行为质量。

## 决策变量

- 测试目标：部署可达、主流程可用、逻辑分支完整或业务链闭环。
- 测试环境：本地、临时集成环境、测试环境、预发布环境或生产只读探针。
- 真实与 Mock 边界：被测服务、外部依赖、认证服务和数据源分别采用何种方式。
- 数据边界：租户、用户、唯一业务键、前置数据、清理/补偿和并发隔离策略。
- 门禁要求：PR、合并、部署前、部署后、夜间和发布分别需要哪些层级。
- 证据要求：请求/Trace ID、响应结构、业务码、状态变化、报告格式和人工确认点。

## 候选方案

- **单层真实冒烟**：实施最快，只能证明少量接口在某个环境可达，无法覆盖逻辑分支和业务链。
- **Mock/单元测试优先**：反馈速度快、适合 PR，但不能证明部署路由、认证配置、真实依赖和环境连接正确。
- **四层组合方案**：用 L1/L2 提供真实运行证据，用 L3 提供快速逻辑与契约反馈，用 L4 验证业务闭环；实施成本最高，但覆盖的失败类型最完整、证据边界最清晰。

## 四层模型

1. **L1 可用性与部署探针**：真实请求健康检查、就绪状态、关键只读路由、认证边界和最小响应契约。它证明“可达”，不证明业务主流程。
2. **L2 真实接口主流程**：在测试或预发布环境使用真实 HTTP、真实认证和标准参数验证关键成功路径。
3. **L3 Mock 逻辑与契约测试**：Mock 外部依赖，覆盖错误、边界、权限、幂等、超时、非法状态和契约校验。
4. **L4 业务逻辑链测试**：在隔离测试范围内按业务顺序串联接口，验证状态变化、前后置条件和清理结果。

## 共享契约

每个接口登记稳定 ID、方法、路径、认证、标准请求、预期状态码和业务码、响应 Schema、前置条件、清理动作、风险级别和所属业务链。四层测试引用同一登记，不在不同测试脚本中复制并各自解释接口含义。

## 数据和环境规则

- L1 只使用无副作用探针或安全只读请求。
- L2/L4 使用独立租户、测试用户、`test_run_id` 和唯一业务键；不得断言共享环境的全局空列表。
- L3 使用临时数据库、容器或受控 Mock；Mock 被测服务本身不能替代真实 L2/L4 证据。
- 每条写入链都必须有清理或补偿动作；清理失败单独标记，不得把测试标记为完整通过。
- 生产环境默认只运行 L1 和明确批准的无副作用只读探针。

## 场景化推荐规则

- 目标是确认部署成功：先做 L1，再做 L2；不要用 Mock 测试代替真实环境证据。
- 目标是提高 PR 反馈速度：优先 L3，关键模块补充短 L4。
- 目标是证明 CRUD 闭环：使用 L4，并让初始查询限定在本次测试创建的隔离范围内。
- 目标是防止 TDD 场景遗漏：在 L3 增加反向矩阵和变异测试，在 L4 增加状态转换链；覆盖率不作为唯一门禁。

## 推荐门禁

```text
PR：L3 契约/逻辑测试
合并：L3 全量 + 关键 L4
部署前：L1 预检查
部署后：L1 + L2
夜间：L3 全量 + L4 全量 + 边界和变异抽样
发布：关键接口 L1/L2/L4 通过，L3 无阻断失败
```

## 反模式

- 把 HTTP 200 当作业务成功，不校验业务码、响应结构和状态变化。
- 只测 Controller 或只 Mock Service，导致路由、认证、序列化和真实依赖错误无法暴露。
- 用固定共享数据跑 CRUD 链，测试之间互相污染。
- 无限重试 flaky 测试，把偶发失败隐藏为通过。
- 用 JaCoCo、行覆盖率或测试数量代替行为断言和场景价值。

## 验证方法

1. 为每个关键服务登记一组 L1、L2、L3 和 L4 用例，并确认每层失败能归类为部署、契约、业务、数据或测试基础设施问题。
2. 故意改变路由、业务码、外部依赖错误和 CRUD 状态，确认对应层次能失败。
3. 使用唯一 `test_run_id` 连续运行两次，确认结果互不污染且清理可重复。
4. 检查 Mock 通过时仍保留真实 L2/L4 证据，不把静态报告或单元测试结果称为部署成功。
