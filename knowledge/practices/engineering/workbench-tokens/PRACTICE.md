# 本地 AI 工具 tokens 用量采集与呈现

## 问题定义

开发者使用多个本地 AI 编码工具，需要汇总用量趋势；不同工具的本地数据暴露形式不同，因此必须先判定可获取性，再选择可重复运行的采集策略。

## 适用场景

- 统计本地 AI 编码工具的 tokens 用量并按天、来源或模型聚合。
- 需要只读本地日志、避免把用户数据上传到外部服务。

## 不适用场景

- 企业多用户计费或依赖云端账单的费用核算。
- 没有公开或可授权本地结构化数据时的远程抓取。

## 决策变量

- 数据源是否包含可识别的用量字段和稳定会话标识。
- 日志是增量事件还是累计快照。
- 日志格式变化、截断和异常行的容错边界。

## 候选方案

- 直接解析稳定的本地结构化日志。
- 为每个工具提供独立适配器，再统一进入采集接口。
- 只展示可验证来源；不可获取工具明确标记为未知而非估算。

## 场景化推荐规则

日志含稳定 usage 字段时可直接解析；出现累计值与增量值并存时优先使用增量；格式可能变化时保留跳过计数和原始定位信息；费用换算必须使用外置、可更新的定价数据。

## 反模式

- 将累计总量重复入库而导致重复计数。
- 仅用高精度 mtime 判断日志变化。
- 在模块加载期建立依赖尚未初始化的数据表。
- 让展示层依赖具体文件路径或日志字段。

## 验证方法

1. 使用临时 JSONL 样本覆盖首轮、重复、追加、重写和异常行。
2. 抽样比对采集结果与原始日志，并验证重复扫描幂等。
3. 验证采集器以只读方式访问用户目录，异常记录可诊断。

## 证据与来源

本 Practice 为 `draft`。2026-08-16 的本机观察显示 Claude Code 与 Codex 日志可提供部分结构化用量事件，但字段和可用性随工具版本变化；尚未完成跨版本兼容性或费用准确性评测。
