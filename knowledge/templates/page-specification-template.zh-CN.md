# 页面设计与实现规格

在创建某个页面/状态的 Figma 底层窗体或目标代码前，为每个获批页面/状态建立一份 `PS-YYYYMMDD-VNN` 规格。它是已批准的项目设计契约、架构、清单、公共组件契约和分层交付之间的页级桥梁。它是评审文档或右侧注释的来源；说明性内容不得放入产品 UI。

## 元数据

```text
specification_id: PS-YYYYMMDD-VNN
status: Draft | Approved | Blocked
PDC_revision:
ARC_revision:
inventory_revision:
feature_id:
page_state_id:
terminal_and_shell:
figma_frame_or_target_path:
owner:
reviewer:
evidence_date:
```

## 终端外框选择（属于 `PS-01`）

| 已声明 target | 所选外框表现 | 可见页面边界 | 尺寸 | Chrome、安全区和导航面 | 证据 | 决策 |
|---|---|---|---|---|---|---|
| web / miniapp / app-* | 浏览器外框 / 有边界视口 / 小程序外框 / 声明设备 | 必须包围完整页面 |  |  |  |  |

使用目标终端的实际证据。Figma 页面不得是裸画布：`web` 使用批准的浏览器外框或边界可见的视口容器；`miniapp`
使用适用的小程序外框；`app-*` 使用声明的设备和安全区外壳。通用手机框不能代替其他终端。只有浏览器 Chrome 不属于产品契约时
才能省略它；视口边界仍必须可见。

## 4. 分层的 Figma 与实现计划（`PS-04`）

| 层级 | Figma 构建 | 目标实现 | 进入下一层前的证明 |
|---|---|---|---|
| L0 结构底层 | 终端外框、页面根、区域、正常流/Auto Layout 父级、状态槽、右侧注释同级块 | 路由/入口、外框、页面根、布局责任层、状态槽 | BF-01–BF-06 和页面外框证据 |
| L1 公共基础 | 已批准的组件、变体、Token、动作组、Icon、资产 | 既有/项目组件、Token、Code Connect 映射 | PS-03 映射和 AGC/ICON 门禁 |
| L2 页面编排 | 元素层级、已核验/待评审产品文案、数据和重要状态 | 页面编排、数据/状态连接、正常流布局 | 元素覆盖且重要状态已出现 |
| L3 范围内完成 | 页面特有视觉样式、已批准的浮层、交互细节 | 范围内样式、资产、响应式规则、交互细节 | 没有页面本地组件克隆或补偿式几何 |

前一层缺失、失败或为 `Unverified` 且没有获批例外时，不得开始后一层。
