# 接口四层测试

使用本 Skill 将接口测试请求转为有边界、有证据的四层测试方案或执行报告。必须把部署可达性、真实接口行为、隔离逻辑测试和多请求业务链作为不同证据类别记录。

## 输入契约

- 必需：目标服务/接口范围、测试目标、可用环境、认证边界和所需证据。
- 执行必需：接口契约或清单、标准请求、预期状态码/业务码、测试数据范围和清理策略。
- 可选：技术框架、执行器、OpenAPI、现有 Fixture、依赖关系、CI 入口和风险标签。
- 一个阻断性澄清：目标环境或数据安全边界未知时，停止真实写请求，并将运行时证据标记为 `Unverified`。

## 工作流

1. **范围与清单**：确认服务、接口、调用身份、环境、副作用、重要性和排除项，生成或引用稳定接口 ID。
2. **契约基线**：记录方法/路径/认证、标准请求、HTTP 与业务结果、响应结构、前置条件、清理动作和所属业务链；缺失值不得猜成事实。
3. **L1 可用性探针**：对声明的部署执行安全健康/就绪和关键只读探针，验证可达性、响应类型、最小结构、认证边界和有限延迟。部署证据与业务成功分开报告。
4. **L2 真实冒烟**：通过真实传输、标准参数和真实认证调用已部署服务，验证 HTTP 状态、业务码、结构、关键不变量和请求关联 ID。除非写入范围已获批准，只使用隔离或无副作用数据。
5. **L3 Mock 逻辑与契约**：Mock 外部依赖，覆盖正常、非法、边界、认证、权限、无资源、超时、依赖错误、幂等、并发、分页和非法状态；有契约时校验 Provider/Consumer Schema。
6. **L4 业务链**：在独立租户或唯一测试命名空间运行状态链。CRUD 应限定查询范围，依次新增、列表数量增加、查询详情、更新、确认详情、删除、确认不存在、列表数量减少并清理。不得要求共享环境全局为空。
7. **分类与报告**：按 `DEPLOYMENT_UNAVAILABLE`、`CONTRACT_DRIFT`、`BUSINESS_FAILURE`、`AUTHORIZATION_FAILURE`、`TEST_DATA_FAILURE`、`DEPENDENCY_FAILURE`、`TEST_INFRA_FAILURE` 分类；记录接口 ID、环境、运行 ID、请求 ID、断言和首个失败步骤。
8. **交接与门禁**：将结果映射到 PR、合并、部署前、部署后、夜间或发布门禁，记录未验证运行边界和下一步授权。

## 四层门禁

| 层级 | 证据 | 典型门禁 | 不得声称 |
| --- | --- | --- | --- |
| L1 | 部署服务上的真实安全探针 | 部署前/后 | 业务链路正确 |
| L2 | 标准参数的真实 HTTP 请求 | 部署后/发布 | 所有分支已覆盖 |
| L3 | 确定性的 Mock、契约和反向用例 | PR/合并 | 部署健康 |
| L4 | 隔离数据上的有状态多接口链 | 合并/夜间/发布 | 共享数据无关净 |

## 边界

- 未明确目标、数据范围和授权时，不调用生产写接口或修改外部系统。
- 不把 Mock/单元结果当成部署证据；请求未真实执行时，不把生成报告称为运行通过。
- 不使用共享可变 Fixture、全局空数据假设或无限重试掩盖状态污染和不稳定性。
- 凭据不得进入清单、Fixture、日志、报告、提示词或源码；通过测试执行器注入并脱敏响应。
- 不因选择本 Skill 就引入框架或外部依赖；优先使用消费项目已有执行器，否则记录采用决策。

## 输出契约

默认使用用户语言返回：

1. `范围与假设`：服务、环境、认证、数据边界、排除项和缺失变量。
2. `接口契约基线`：稳定 ID 和预期结果。
3. `四层矩阵`：L1/L2/L3/L4 用例、真实/Mock 边界、Fixture 和门禁。
4. `执行证据`：命令或执行器、结果、时间/版本、请求 ID 和报告。
5. `失败分类`：首个失败、断言、证据和疑似责任方。
6. `未验证项与人工决策`：缺失环境、写入授权、框架选择和发布批准。

声明某层完成前，必须具备该层声明的运行时或人工证据。

## 完成门禁

- 明确范围、环境、认证、数据隔离、契约和清理策略。
- 四层均已执行并有证据，或已标记 `Unverified` 及阻断原因。
- 每个关键接口至少有一个正向和一个反向用例；每条关键链有顺序状态断言和清理动作。
- Mock 证据和真实运行证据分开报告。
- 报告含稳定接口 ID、运行/Fixture ID、请求 ID、断言结果和首个失败分类。
- 明确 CI/发布门禁和仍需人工确认的事项。
