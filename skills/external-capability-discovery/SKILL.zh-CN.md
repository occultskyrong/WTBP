# 外部能力发现

先发现，再自建。本 Skill 是本地 WTBP 能力发现之后的在线回退，不替代已经明确适配的本地 Skill。

## 输入契约

- 必需：任务目标、期望结果、目标领域或技术栈，以及会影响采用的约束。
- 可选：目标终端、许可证偏好、安全边界、安装授权、时间范围和最低分数。
- 先运行 `wtbp "<请求>"` 确认本地结论。若已有一个已登记本地 Skill 明确满足请求，直接返回该选择，不进行在线发现。
- 若目标、产物或约束缺失，只询问进行候选比较所需的最小信息。

## 工作流

1. 记录本地结果：已选择的本地能力、因不足而排除的候选，或 `no_match`。仅关键词命中不等于本地适配。
2. 根据目标、技术栈、终端和期望产物规划不超过五个按来源区分的查询，并说明搜索范围与检查日期。
3. 分层检索，并且只有在当前会话打开来源后才将其作为证据：
   - 对可安装 Agent Skill 使用 `find-skills` / skills.sh，先查看排行榜再进行细化搜索；
   - 在 GitHub 中寻找 `SKILL.md`、官方集成、持续维护的仓库或参考实现；
   - 优先搜索第一方文档与原始材料，再使用二手列表；
   - 对公开网络证据、引用、冲突和不可访问页面遵循 `systematic-cognition` 的来源规则。
4. 为每个相关结果建立临时候选卡，只收集当前会话已核验的事实：来源 URL、发布方、类型、支持任务、适用时的安装量、GitHub Star/Fork、可观察的活跃贡献者、近 180 天提交数、最近提交或 Release 日期、许可证、固定修订可用性、Skill 路径、权限与副作用。
5. 阅读 [scoring-model.md](references/scoring-model.md)。为每个候选计算 0–100 分，保留五项分项分数和原始指标，单独计算证据置信度，并按总分排序。不得编造缺失指标，也不得在不说明原因时把不可获得指标视作零分。
6. 为每个候选给出一个采用建议：`direct-use`、`adapt`、`compose`、`reference-only`、`reject` 或 `build-local`。说明第一名为何优于第二名，以及仍需要哪些人工确认。
7. 在安装、登记写入、代码执行、凭据访问或项目修改之前停止。只有用户确认且另行通过 WTBP 治理审查的候选，后续才可以登记或安装。

## 边界

- 仅读取公开来源。不得登录、绕过访问控制、读取私有仓库、下载可执行文件、安装包、运行未知代码或访问凭据。
- skills.sh 只是一个发现来源，不是质量证明；`find-skills` 不替代 GitHub、许可证、维护或安全核验。
- 不得宣称穷尽 GitHub 或全网。搜索结果、仓库标题、Star 数或模型记忆都不能单独证明适配性。
- 发现的候选保持临时状态。未经用户明确确认和常规审查门禁，不得写入 `knowledge/external-sources.yaml`、`knowledge/external-capabilities.yaml` 或 `knowledge/skill-routes.yaml`。
- 分数只对当前证据排序，不是安全批准、行为评测或安装授权。

## 输出契约

使用用户语言；本仓库默认中文。包含：

```text
本地优先结论与搜索范围
已排序候选表：排名、总分 / 100、证据置信度、采用建议
每个候选的分项分数、来源链接、来源类型、原始采用与维护指标、许可证、修订/路径、权限与检查日期
第一名与第二名的排序差异
未核验或不可获取的指标及其评分影响
建议的下一步授权；未执行安装
```

## 完成门禁

- 在线发现前已选择本地能力、基于证据排除本地能力，或明确标记 `no_match`。
- 每个参与排序的候选都有当前会话已打开来源和透明的 100 分总分；不可获取的指标已披露。
- 输出明确区分总分与证据置信度，仅对可比较候选排序，不包含伪造的指标、引用、权限或版本。
- 未安装、执行、持久化外部内容或授予访问权限；否则必须报告发现未完成。
