# Figma 到产品实现

根据当前 Figma 设计证据实现一个 target。不得重新从 PRD 开始、补全缺失业务功能，或把截图视为完整设计契约。

实现前先读取 [`../../knowledge/design-principles.zh-CN.md`](../../knowledge/design-principles.zh-CN.md)，再读取 [`../../knowledge/design-workflow.zh-CN.md`](../../knowledge/design-workflow.zh-CN.md)。两者共同定义分层设计契约、简报/清单门禁、证据来源、完整页面要求、文案分类和真实夹具验收契约。

## 输入契约

- 明确的 Figma 页面、Frame、组件或状态节点链接。
- 一个 target：`web`、`miniapp`、`app-ios`、`app-android`，或其他明确命名的 target。
- 终端外框契约：准确视口/设备尺寸、设备/浏览器外壳、安全区、导航/状态面，以及包围完整页面的可见边界。`miniapp` 必须展示适用的小程序外框；`app-*` 必须展示声明的设备/安全区 Chrome；`web` 必须展示批准的浏览器外框或边界可见的视口容器。不得用裸画布或通用手机框代替其他 target。
- 目标仓库或可写实现位置。
- 已批准的设计清单/契约及其功能 ID，或足以确认已批准范围的证据。
- 已批准的项目设计契约 `PDC-YYYYMMDD-VNN`，或允许在目标仓库中先建立契约的权限和证据。
- 每个声明页面/状态已批准的 `PS-YYYYMMDD-VNN` 页面规格，或足以在目标实现前建立它的证据。
- 已批准的 `ICON-YYYYMMDD-VNN` 清单，或足以在实现前重建其语义 Icon 映射的证据。
- 已批准的动作组契约 `AGC-YYYYMMDD-VNN`，或足以在实现页面样式前推导该契约的证据。

target、仓库或项目契约证据缺失时询问。Figma 设计与提供的 PRD 或项目设计契约冲突时，报告冲突并交给 `figma-evolve`，不得在代码中自行选择。

## 设计证据门禁

1. 记录 `EX-01`，再在 `get_design_context` 前加载官方 `figma:figma-design-to-code`；需要检查 Figma 时加载 `figma:figma-use`。官方能力不可用时把证据标记为 `Unverified`；不得安装第三方替代物。
2. 对每个范围节点收集节点和父级 ID、层级、截图、Auto Layout、约束、变量/Tokens、组件/Variants、标注/原型行为及精确资源/字体。
3. 检查目标仓库实际的路由、页面族、组件、主题/Tokens、CSS 或平台样式、资源、运行入口和终端约束。先创建或刷新 `PDC-YYYYMMDD-VNN`，记录 `PDC-01`–`PDC-06`，再选择架构或实现映射。优先级为 Code Connect 映射、项目既有组件/Tokens、Figma Variables；最后才新建最小组件。
4. 可复用 Figma 组件需要持久代码映射时使用 `figma:figma-code-connect` 并记录 `EX-02`；映射不可用时不得声称已精确复用组件，但不阻断实现计划本身。
5. 编辑前先基于已批准项目设计契约推导或确认 `ARC-YYYYMMDD-VNN`。映射模块、路由、外框、复用边界、状态/转移和完整底层窗体批次；然后为每个声明页面/状态建立或确认含 `PS-01`–`PS-05` 的 `PS-YYYYMMDD-VNN`。用页面规格中的元素层级与复用矩阵，选择项目组件、Code Connect、Tokens、字体、Icon、资产和布局责任层，并确认 L0–L3 实现顺序。实现请求改变范围、页面结果、元素层级、组件契约或终端约束时，回到最早受影响的契约门禁，不得自行补全。
6. 实现页面样式前，建立或确认 `AGC-YYYYMMDD-VNN` 并通过 `AGC-01`–`AGC-06`。将每个动作组映射到项目组件及已声明的宽度/插槽策略。对称导航必须使用左右等大的触达插槽，并将中部操作相对父级居中；仅使用 `space-between` 不能证明居中。
7. 实现页面样式前，建立或确认 `ICON-YYYYMMDD-VNN` 并通过 `IA-01`–`IA-07`。把每个 Figma Icon 实例映射到语义组件、尺寸、风格、状态、精确来源/导出及目标实现。优先复用项目库；缺失 Icon 必须在使用前按批准资产家族独立设计，绝不能作为页面局部替代物。
8. 在任何页面样式之前，确认每份页面规格，并为所有声明页面/状态实现 L0 结构底层批次：可见地包围完整页面的所选终端外框/视口边界、页面根节点、内容区域、正常流/Auto Layout 父级、状态插槽和右侧注释同级块。本批次使用中性内容，不加入页面级装饰。
9. 对整批执行并记录阻断检查点（`BF-01`–`BF-06`）。底层批次失败或不完整时，阻断组件样式和内容润色。
10. 每次实现写入后，对所有声明的页面/状态执行共享结构门禁（`G-01`–`G-06`）：记录源 Figma 的 `layoutMode` 或 DOM 布局责任层、导航分布、页面与右侧注释一一对应、递归后代边界、共享组件实例与 Master 的宽高比例、终端外框高保真和产品内容隔离。缺少任一结果时不得交给 `figma-verify`。

## 布局溯源门禁

不得把 Figma `x/y` 坐标直接翻译为普通内容的 CSS `left/top`。将每个关键子元素分类为正常流、约束/拉伸、浮层或 fixed/sticky。

每个关键视觉差异或 absolute 子元素都要向上追踪至页面根，识别布局责任层。检查 `display`、`position`、尺寸、padding、margin、gap、box sizing、flex/grid 规则、overflow、transform、继承字体、变量及响应式规则。

- 普通内容使用 Flex、Grid、Auto Layout 意图和正常文档流。
- `absolute` 仅允许已证实的浮层、角标或锚定控件；记录定位父级、锚点和已验证 viewport。
- 修复第一个发生偏差的布局责任层；不得用子元素 margin、transform 或坐标补偿掩盖父级错误。

## 动作组契约门禁

只能依据已批准的 `AGC-YYYYMMDD-VNN` 记录实现操作控件。可见 Icon 与可点击/可触达目标是两个独立数值：保持批准的视觉尺寸，同时通过共享 Tokens 实现已声明的目标尺寸。

- 只有批准的容器语义明确为单一操作时，`single-action` 才可使用一个占满区域的目标。
- `action-group` 与 `segmented-selection` 必须使用声明的 `content`、`equal` 或 `full-span` 宽度策略，以及 `natural`、`equal-slot` 或 `equal-partition` 插槽策略。不得为了填满可用宽度，把多个操作伪装成一个带大外框的按钮。
- `symmetric-navigation` 必须分配相同的上一步/下一步目标插槽，并把中部操作相对父级居中，而不是相对剩余空间居中。CSS 优先使用三轨 Grid，例如 `grid-template-columns: var(--agc-edge-target) minmax(0, 1fr) var(--agc-edge-target)`，中部子项使用 `justify-self: center`；其他平台使用等价原生实现。
- 页面局部宽度、margin、transform、手工坐标或 `space-between` 补丁不得覆盖已登记的动作组契约。应修复共享组件/Token 或首个布局责任层。
- 记录 `AGC-01`–`AGC-06` 的几何证据；对称导航还须记录左右目标尺寸相等，且 `abs(middle.centerX - parent.centerX) <= declared tolerance`。
- 第三方设计 lint 或可访问性 Skill 只属于可选审计：需要用户明确授权和 `EX-03`–`EX-04`，且不能替代 DOM 几何、运行时或人工复核证据。

## 问题驱动的实现场景

编辑前选择全部适用场景，并在实现计划中写明 ID、target、Figma 节点、预期布局责任层和所需 viewport/状态。在捕获所需证据前，视为未通过。

| ID | 给定条件 | 必须实现与断言 |
|---|---|---|
| I-01 正常流卡片 | 卡片的标题、可变长度文案、图片和 CTA 按阅读顺序出现。 | 将 Figma Auto Layout 映射为正常流/Flex/Grid。断言改变文案长度后，下游内容由父级布局移动，而不是子元素 `top/left`。 |
| I-02 锚定浮层 | 角标、关闭按钮或菜单覆盖在卡片上。 | 只允许在已命名的包含父级、锚点和 viewport 下使用 absolute。断言普通内容增长时它仍保持锚定。 |
| I-03 祖先 padding 偏移 | 卡片整体比 Figma 偏离 12–16px。 | 对比完整祖先链，修复第一个错误的 padding、gap、宽度或布局方向；断言不存在补偿性子元素 margin/transform。 |
| I-04 层叠或包含块偏移 | 全局选择器、`box-sizing`、`transform`、`overflow` 或定位祖先改变几何关系。 | 定位计算样式来源和包含块。断言作用域规则获胜，且不削弱无关页面。 |
| I-05 字体与资源偏移 | 回退字体、line-height、未加载图片或错误 `object-fit` 改变内容高度。 | 使用精确资源/字体，并在运行证据中等待其就绪。断言文本/图片几何正确后再比较间距。 |
| I-06 响应式约束偏移 | Figma Frame 在多个宽度下都应正常工作。 | 实现声明的 Flex/Grid/约束规则，并分别断言各 viewport；不得只验证设计 Frame 宽度。 |
| I-07 Target 隔离 | 请求只声明一个 target。 | 只按该终端的原生约定实现。断言不得声称实现了未列出的 Web、小程序或 App。 |
| I-08 等权导航分布 | TabBar、Tabs 或分段控件要求等权子项或明确分区。 | 使用 Auto Layout/Flex/Grid 或等价分布规则。根据声明的分区断言子项权重/基准宽度和中心点；不得手写 `x/y` 或 `left/top` 摆放。 |
| I-09 递归组件边界 | 页面包含嵌套卡片、按钮、文字、媒体或共享组件实例。 | 遍历所有后代及其直接父级/祖先链。断言子节点不越过要求的边界，且不存在用 `overflow:hidden` 掩盖问题；只检查页面级边界不算通过。 |
| I-10 对称导航契约 | 上一步与下一步控件围绕“本月”等中部操作。 | 使用批准的 `symmetric-navigation` 组件，左右目标插槽相等且中部子项相对父级居中。断言左右目标宽高相等、中部中心偏差不超过声明容差；拒绝手工坐标和仅用 `space-between` 证明居中。 |

I-03 至 I-06、I-08 至 I-10 必须把失败和通过的截图交给 `figma-verify`；代码 diff 本身不能关闭用例。

## 工作流

1. 检查目标项目并创建或确认 `PDC-YYYYMMDD-VNN`；不得只凭 Figma 推断路由、组件、Tokens、行为或约束。
2. 推导或确认 `ARC-YYYYMMDD-VNN`，再为每个页面/状态建立或确认 `PS-YYYYMMDD-VNN`：先写页面说明和边界，完整盘点元素层级，明确 `reuse`、`extend` 或 `new` 的公共组件/Token/Icon/资产映射，并写出 L0–L3 计划与设计到代码映射；然后才编辑代码。
3. 页面样式前确认 `AGC-YYYYMMDD-VNN` 并通过 `AGC-01`–`AGC-06`。把每个动作组映射到原生组件/CSS 实现及其声明的语义、宽度策略、目标尺寸和插槽策略；对称导航必须使用左右等大插槽和相对父级居中的中部操作。
4. 页面样式前确认 `ICON-YYYYMMDD-VNN` 并通过 `IA-01`–`IA-07`。把每个实例映射到语义 ID、组件、尺寸、风格、状态、精确来源/导出和目标实现；缺失 Icon 必须独立设计为家族风格一致的组件。
5. 选择所有适用的 I-01–I-10 用例，并在编辑前记录 target、节点、预期布局责任层、viewport、状态和所需失败证据。
6. 按目标项目既有约定与页面规格，为所有声明页面/状态实现 L0 完整结构底层批次，包含可见地包围完整页面的所选终端外框/视口边界；保护无关代码，不得提交、推送或修改其他 target。
7. 执行并记录 BF-01 至 BF-06；底层批次通过前不得添加组件或视觉样式。
8. 依页面规格按层叠加：L1 公共基础与可复用组件，L2 页面编排、产品内容和重要状态，L3 有范围的视觉样式与交互完成度。在声明的终端外框内渲染完整容器页面和重要状态，不得交付裁剪组件。新增产品文案要分类，页面描述、项目/技术说明和设计说明放在产品 UI 外的右侧注释同级块中。
9. 使用精确 Figma 资源和已批准 Icon 映射；不得绘制页面局部替代图标、改变 Icon 已批准的尺寸/风格/状态，或静默回退系统字体。
10. 为每个声明的 viewport/状态运行目标检查并捕获确定性运行证据。代码 diff 或单张截图不是验收；将完整夹具交给 `figma-verify`。
11. 交接时附上项目设计契约和 PDC 结果、动作组契约/AGC 结果、Icon 清单/IA 结果、终端外框契约、底层批次证据和 BF 结果、完整外框截图、覆盖所有页面的 G-01 至 G-06 写入后门禁记录、操作/转移结果和已审批例外；不得只凭变更组件报告实现验收。

## 输出契约

返回：

```text
Figma 节点和 target/仓库
项目设计契约修订号、PDC-01 至 PDC-06 结果、推导出的架构修订号（`ARC-YYYYMMDD-VNN`）和证据边界
页面规格 ID、`PS-01`–`PS-05` 结果、元素/复用矩阵、L0–L3 实现记录和设计到代码映射
动作组契约修订号、组件/Token 映射和 `AGC-01`–`AGC-06` 结果
Icon 资产清单修订号、逐实例语义映射和 `IA-01`–`IA-07` 结果
终端外框契约和尺寸
底层 Frame 批次、中性截图和 BF-01 至 BF-06 结果
已批准的清单和功能 ID
设计证据及组件/Token 映射
已修改实现文件
布局责任层和已批准的 absolute 定位案例
完成的检查和截图
运行矩阵、文案分类、可访问性证据和夹具记录
已知视觉/行为缺口
供 figma-verify 使用的节点到代码链接
```

## 完成门禁

- 已明确目标终端、仓库、项目设计契约（PDC-01 至 PDC-06）、推导出的架构（`ARC-YYYYMMDD-VNN`）、每个页面/状态的页面规格（`PS-01`–`PS-05` 的 `PS-YYYYMMDD-VNN`）、动作组契约（含 `AGC-01`–`AGC-06` 的 `AGC-YYYYMMDD-VNN`）、Icon 清单（含 `IA-01`–`IA-07` 的 `ICON-YYYYMMDD-VNN`）、清单和适用的 I-01 至 I-10 用例。
- 每个声明页面/状态先通过 BF-01 至 BF-06；运行证据覆盖每个声明的视口/状态和终端外框，且写入后的 G-01 至 G-06 记录完整。
- 不得声称完成未声明的终端或未经证明的坐标补偿；缺失证据时禁止交接。
