# 验证 Figma 落地

以实际实现证据验证当前 Figma 设计证据。本 Skill 不假设每次交付都包含 Web 和小程序；只验证声明的 targets。

验证前先读取 `../../knowledge/design-capability-selection.zh-CN.md`、`../../knowledge/design-principles.zh-CN.md`，再读取 `../../knowledge/design-workflow.zh-CN.md`。它们共同定义能力选择、分层范围、证据优先级、清单审批、完整页面覆盖、标注几何、文案分类、可访问性和真实夹具验收的共享契约。

## 输入契约

- 被验收页面、状态或组件的明确 Figma 节点链接。
- 至少一个已声明 target 及其可运行产品、预览或仓库。
- 验收矩阵：viewport/设备和关键状态。PRD 已提供时使用 PRD；否则只询问缺失的验收维度。
- 终端外框契约：外框类型、准确尺寸、设备/浏览器外壳、安全区、导航/状态面，以及包围完整页面的可见边界。`miniapp` 必须验证小程序外框，`app-*` 必须验证声明的设备/安全区 Chrome，`web` 必须验证批准的浏览器外框或边界可见的视口容器；通用移动端 Frame 或裸画布均不能通过。
- 已审批的设计清单和稳定 feature ID。若没有已审批清单，必须依据权威需求重建最小清单，并在审批前标记为 `Unverified`；未经审批的范围不得声称验收通过。
- 已批准的项目设计契约 `PDC-YYYYMMDD-VNN`，或足以在比对实现一致性前从仓库重建契约的证据。
- 已由契约推导的架构记录 `ARC-YYYYMMDD-VNN`；如果目标包含项目架构但记录缺失或过期，必须停止并回到契约/架构门禁。
- 每个声明页面/状态已批准的 `PS-YYYYMMDD-VNN` 页面规格，或足以在验收前重建它的证据。
- 已批准的 `ICON-YYYYMMDD-VNN` 清单，或足以在接受视觉一致性前重建清单的项目证据。
- 已批准的动作组契约 `AGC-YYYYMMDD-VNN`，或足以在接受控件几何一致性前重建该契约的项目证据。
- 模式：默认 `report`；仅用户明确授权有范围的实现改动时才用 `fix`。

## 边界门禁

使用 `design-workflow.zh-CN.md` 中的共享边界模型。终端外框、产品根 Frame、声明的系统 Chrome、产品 TabBar、Section 与右侧说明块必须分别登记归属。`Canvas` 与 Figma 选中样式只是编辑器对象，不能作为交付证据；Section 不能替代外框或产品根。`G-05S` 验证层级、尺寸和包含关系；`G-05V` 必须在**未选中**、固定视口/缩放的完整外框截图中验证符合目标的填充、描边或原因、圆角或原因、阴影或 Chrome、画布对比，并独立展示带画布留白的上/右/下/左四边。`G-05S` 结构通过但 `G-05V` 未通过，是验收失败而非警告。

## 工作流

1. 在比对验收证据前创建或刷新 `DCS-YYYYMMDD-VNN`。运行 `wtbp "<任务>"`，选择本 Skill 及按需的视觉方向/Icon/动效/Code Connect 分支，记录采用方式和查阅的外部能力卡 ID。只有本地和已收录外部能力均无明确适配时才在线发现；只有用户明确说出 `wtbp，收集 <公开 URL>` 时才收录 URL。两条路径均不授权第三方安装或执行。
2. 确认输入契约、当前项目设计契约（`PDC-YYYYMMDD-VNN`）、页面规格（`PS-YYYYMMDD-VNN`）、动作组契约（`AGC-YYYYMMDD-VNN`）、当前 Icon 清单（`ICON-YYYYMMDD-VNN`）、`EX-01` 可用性和模式，在比较前建立目标/视口/状态矩阵。
3. 获取稳定的 Figma 和运行证据，执行结构与布局门禁，分类每项差异。
4. `fix` 模式只修复首个已证明的原因，重新运行受影响矩阵并保留前后证据。
5. 产出验收记录，列出未验证项和需要人工复核的内容。

## 证据与矩阵门禁

1. 加载适用的 Figma 检查 Skill，获取当前 Figma 截图、层级、Tokens、约束、组件和目标节点 ID。
2. 建立 target 矩阵。一个 target 只有具备适用设备/viewport、状态和运行证据时才有效。`figma-only` 只检查 Figma 完整性，不验证实现一致性。
3. 稳定每次实现截图：正确 viewport/设备、字体和资源加载完成、尽可能确定的数据、无瞬态动画状态。
4. 确认项目设计契约和推导出的架构是最新的，并根据 `PDC-01`–`PDC-06` 与 `ARC-YYYYMMDD-VNN` 比对实现：项目目标、路由/页面族、设计基础、行为/约束、复用边界、架构关系和证据。契约或架构缺失、过期或存在实质冲突时阻断验收。
5. 确认每个声明页面/状态的 `PS-YYYYMMDD-VNN`：核验 `PS-01` 页面说明与边界、`PS-02` 完整元素清单与层级、`PS-03` 复用映射、`PS-04` L0–L3 构建顺序，以及 `PS-05` 设计到代码/验收映射。页面规格缺失、过期、不完整或与契约冲突时阻断验收。
6. 确认 `AGC-YYYYMMDD-VNN` 和 `AGC-01`–`AGC-06`。核验每个动作组的语义分类、组件复用、宽度/插槽策略、可见尺寸与触达目标尺寸、状态/可访问性证据和几何。对称导航还须记录左右目标宽高相同，以及 `abs(middle.centerX - parent.centerX) <= declared tolerance`；仅用 `space-between` 或一个占满宽度的伪按钮均不通过。
7. 确认 `ICON-YYYYMMDD-VNN` 和 `IA-01`–`IA-07`，再检查每个可见 Icon 实例的语义 ID、批准组件/家族、尺寸、风格、状态、来源/导出和目标映射。页面局部 Vector、emoji、文字图标、裁切图、错误尺寸 Variant 或未经批准来源都会阻断视觉验收。
8. 确认已审批清单和 feature ID 均被覆盖。验证完整容器页面和按 target 选择、尺寸已批准的终端外框，不只验证裁剪组件：先记录外框/产品根/系统 Chrome/TabBar/Section/说明块的归属，再验证外框/视口边界及适用的小程序、App 设备/安全区或浏览器/视口表现；必须验证独立右侧标注块及其几何。
9. 确认所有批准页面/状态均按页面规格在 L1–L3 样式之前完成 L0 底层窗体批次。检查 `BF-01`–`BF-06` 记录和中性截图；底层证据缺失、部分完成或失败时阻断验收。
10. 将所有可见字符串分类为已验证产品文案、`Copy for review`、画布外设计说明或已删除的不支持文案。页面描述、项目/技术说明或验收说明出现在产品 Frame 内时，G-06 失败。
11. 对比结构、布局和视觉结果。评审发现节点迁移、页面增删或 Section 列数变化时，必须依据实际内容边界加已声明的固定内边距，重新计算每个受影响的 Section；记录触发原因、子元素/列输入、内边距、重算前后几何和已批准的固定尺寸例外。旧固定 Section 宽高不能作为有效证据。页面截图是必要条件，但不充分。
12. 对所有产品页面/状态 Frame（包括未修改的 Frame）执行共享写入后结构门禁（`G-01`–`G-06`）：`layoutMode`/布局责任层、导航分布、页面与右侧注释一一对应、递归后代边界、共享实例与 Master 的宽高比例、`G-05S` 外框/产品根包含关系、`G-05V` 未选中固定完整外框截图/视觉配方/画布留白/四边证据，以及产品内容隔离。逐项记录结果和已审批例外。
13. 将原型连线或运行时操作转移与已批准的页面/状态/转移矩阵对照；未追踪的操作、死路或恢复路径属于验收失败，不是视觉细化问题。
14. 只有用户明确授权安装、凭据范围和命令执行（`EX-03`–`EX-04`）后，才能运行第三方设计 lint、Token 或可访问性审计。把来源/版本和发现记录为补充证据；可选审计缺失或失败不能抹除必需的 PS/AGC/BF/G/运行时检查。

## 布局诊断门禁

每个有意义的偏移都必须报告第一个发生偏差的布局责任层，而不是给出子元素级的外观补丁。

沿渲染目标元素和 Figma 对应项各自的祖先链追踪。对比尺寸、padding、margin、gap、flex/grid 方向和规则、position/包含块、overflow、transform、box sizing、字体/line-height、变量和响应式规则。

原因分类为：

```text
structure | action-group-contract | layout-owner | positioning | typography/assets | cascade | environment | unresolved
```

不得仅因差异阈值较小、静态检查通过或一张截图看起来合理，就标记验收通过。蓄意视觉差异和交互质量仍需人工判断。

## 修复模式

`mode=fix` 时，只修改第一个已证实原因，重新执行受影响矩阵项，并返回前后证据。不得通过补偿性子元素 margin、transform 或 absolute 定位掩盖父级错误。

## TDD 式保真用例

每个适用用例都要先捕获可复现的失败状态，再以相同 target、viewport/设备、状态、Figma 节点、字体、资源和数据证明有范围的根因修复。排查期间不得替换失败基线。

| ID | 可复现失败 | 必须诊断 | 通过证明 |
|---|---|---|---|
| V-01 absolute 误用 | 普通卡片内容会随文本或图片高度变化而偏移。 | 分类正常流与浮层，并检查包含块。 | 动态内容截图符合 Figma 意图，且没有坐标补偿。 |
| V-02 父级链遗漏或过期的 Section 边界 | 整个区块以固定距离偏移，或评审发现节点迁移、页面增删或列数变化后仍保留旧 Section 宽高。 | 比对祖先链，找到第一个发生偏差的 padding/gap/尺寸/布局规则；根据实际子元素/列边界加已声明固定内边距重算 Section。 | 已记录责任层和重算内容边界；除非有已批准产品规则，否则不存在过期固定尺寸或子元素补偿。 |
| V-03 层叠/几何泄漏 | 正确的局部样式输给全局选择器、transform、overflow 或盒模型规则。 | 记录获胜的计算样式及来源。 | 有作用域的修正解决目标，且声明矩阵内无回归。 |
| V-04 字体/资源不稳定 | 文本换行不同，或媒体加载后布局变化。 | 视觉差异前验证字体加载、line-height、图片固有尺寸和裁切行为。 | 重复稳定截图显示预期几何。 |
| V-05 响应式偏移 | 一个宽度正确，另一个宽度失效。 | 对比每个声明 viewport/设备与 Figma 约束。 | 每个声明 viewport/状态都有独立结果。 |
| V-06 状态遗漏 | 默认态正确，但加载/错误/禁用态不同。 | 对比 Figma Variant 或状态 Frame 与运行时状态。 | 每个声明状态都通过、失败或明确阻塞。 |
| V-07 Target 泄漏 | 请求只声明一个平台，报告却声称跨端验收。 | 检查 PRD/设计契约的 target 列表。 | 报告只含声明 targets；未列 targets 标为 `not requested`。 |
| V-08 导航分布漂移 | TabBar 或分段导航看似等分但实际不等分。 | 检查 Auto Layout/Flex/Grid 分布、子项权重/基准宽度、分区中心点和容差；除非产品契约有解释，否则拒绝手工坐标。 | 所有声明的目标 viewport 下，导航子项都满足分布契约。 |
| V-09 递归子节点溢出 | 页面外框通过，但内部卡片、按钮、文字、媒体或共享实例裁剪/越过父边界。 | 递归遍历所有后代，比较直接父级和祖先几何；检查 overflow/裁剪，并记录第一个偏差责任层。 | 所有后代都通过边界检查，或记录准确的已批准溢出/浮层例外。 |
| V-10 Icon 资产漂移 | Icon 看似合理，但使用页面局部 vector、错误库、错误视觉尺寸、错误描边/风格或未声明状态。 | 追溯实例至 `ICON-YYYYMMDD-VNN`；对比语义 ID、组件/家族、尺寸、风格、状态、来源/导出和目标映射。 | 每个可见 Icon 都映射到已批准条目和渲染实例；缺失 Icon 有独立、家族风格一致的组件和 IA 记录。 |
| V-11 对称导航几何漂移 | 上一步/下一步控件视觉过小或不等大，中部操作未相对父级居中，或动作组是一个过大的带边框伪按钮。 | 追溯控件至 `AGC-YYYYMMDD-VNN`；检查语义类型、共享组件、宽度/插槽策略、可见尺寸与触达目标尺寸及父级中心。 | `AGC-01`–`AGC-06` 通过：左右目标几何相等、中部中心偏差在容差内、状态已批准，并使用相同 target/viewport 捕获。 |
| V-12 视觉外框歧义 | 外框/产品根几何存在，但评审者只能借助 Figma 选中框、Section/卡片边缘或无边/裁剪截图看到边界。 | 区分画布、选中框、终端外框、产品根、Section 与说明块；检查声明的视觉配方和带画布留白的未选中固定视口/缩放截图。 | `G-05S` 与 `G-05V` 均通过：四条外框边独立可见、没有选中样式，且内容/TabBar/产品根/系统 Chrome 归属正确。 |

在 target 矩阵中使用这些用例 ID。只有失败基线、首个原因诊断、获授权时的修复证据和修复后捕获都齐全，用例才算**通过**。

## 真实夹具契约

要声称某个用例已经解决，必须为该用例保存或返回以下最小证据：

```text
case_id、Figma 文件/节点 URL、target、仓库/预览
viewport 或设备、状态、确定性数据和捕获条件
失败基线截图、预期 Figma 截图、修复后截图
首个布局责任层及计算样式/几何证据
已改文件或 Figma 节点、复跑结果、人工复核结果
```

提示词级用例只能证明 Agent 遵循流程，**不能**证明某个 CSS 实现已经修复。只有具备这份真实夹具证据，才能把用例升级为已解决。

## 验收门禁

验收记录只有同时包含项目设计契约修订号、推导出的架构修订号（`ARC-YYYYMMDD-VNN`）以及 `PDC-01`–`PDC-06`/架构对照结果、每个页面/状态的页面规格 ID 与 `PS-01`–`PS-05` 结果、动作组契约修订号和 `AGC-01`–`AGC-06` 结果、Icon 资产清单修订号和 `IA-01`–`IA-07` 结果、清单版本/feature ID、终端外框契约、底层 Frame ID 和 `BF-01`–`BF-06` 结果（含 `BF-02S`/`BF-02V`）、target 矩阵、完整页面和物料状态的完整外框截图、预期与实际几何、适用时的标注边界、外框/产品根 ID 与边界、视觉配方、固定未选中截图条件、四边结果、所有页面的 `G-01`–`G-06` 结果（含 `G-05S`/`G-05V`）、文案分类与来源、可访问性检查（对比度、非颜色状态、HTML 的键盘/焦点行为）、第一个布局责任层，以及授权修复后的复跑结果时才算完整。提示词、生成代码、节点创建、静态检查、一张截图或 Skill 评估 dry-run 都不是验收证据。

## 完成门禁

- 每个声明的目标、视口、状态、页面和交互都有独立结果。
- 每个声明页面/状态均有当前的 `PS-YYYYMMDD-VNN`，并已核验 `PS-01`–`PS-05`、元素/复用映射及 L0–L3 实现顺序，或明确阻断原因。
