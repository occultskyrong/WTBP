# PRD 到 Figma

把 PRD 转为可编辑的 Figma 产物。PRD 是唯一业务事实来源；不得检索知识库、依赖 Lark CLI，或补充没有依据的产品规则。

开始前先读取 [`../../knowledge/design-principles.zh-CN.md`](../../knowledge/design-principles.zh-CN.md)，再读取 [`../../knowledge/design-workflow.zh-CN.md`](../../knowledge/design-workflow.zh-CN.md)。前者定义分层设计契约，后者提供共享的最小简报、冲突、变更清单审批、Frame/注释、文案分类和产物验收门禁。

## 输入契约

- PRD 文本、文件或可访问链接。
- Figma 落点：已有文件链接，或用户明确要求新建文件。
- 设计所服务的现有项目仓库/工作树和预览入口；如果是全新项目或 `figma-only` 产物，必须明确记录这个边界。
- PRD 已声明时的目标终端（`web`、`miniapp`、`app-*`）；`figma-only` 合法。
- 终端外框契约：外框类型、准确视口/设备尺寸、安全区和导航/状态面。`miniapp` 必须明确要求适用的小程序外框，不得凭空添加通用设备框。
- 项目已有时的当前 Icon 库/来源；没有时，必须明确所需 Icon 只是待项目接纳的设计候选资产。
- 最小简报：目标结果、角色/终端、产品/平台、入口/主流程、范围/排除项和视觉意图。

只有缺失项会改变页面结构、业务行为或交付落点时，才询问那一个缺失项。不得编造终端、角色、权限、流程或未说明状态。

## 工作流

1. 用只读身份/权限证明预检可调用的官方 Figma 集成，并记录 `EX-01`。在声明的 Figma 范围内使用 `figma-use`；能力不可用时不得安装或替换为第三方工具。
2. 阅读 PRD，返回认知记录和简洁设计契约：目标、角色、终端、入口和旅程、范围内页面、关键状态、targets、排除项和开放/冲突规则。实质冲突要提供不同解决方案并停止。
3. 在设计架构前检查消费项目，创建 `PDC-YYYYMMDD-VNN` 并通过 `PDC-01`–`PDC-06`：项目身份/目标、路由和页面族、设计基础、行为/平台约束、复用/变更边界及证据/决策。项目不可访问时，记录 `figma-only`/全新项目范围，并将依赖实现的字段标记为 `Unverified`。
4. 解决项目契约冲突，并在选择新模块、路由、页面族或视觉基础前，获得项目设计契约审批。然后基于已批准 PDC 推导 `ARC-YYYYMMDD-VNN`，映射模块、路由、外框、复用边界、状态/转移和完整底层窗体批次；架构不得引入契约中没有记录的事实。
5. 创建 `INV-YYYYMMDD-VNN`，包含稳定功能 ID、`Existing — reuse/modify`、`New`、`Conflict` 或 `Unverified` 状态、页面/状态、证据定位和冲突/决策区。Figma 修改、动作组契约或 Icon 抽取前必须获得该清单的明确审批；它是 `AGC-YYYYMMDD-VNN` 和 `ICON-YYYYMMDD-VNN` 唯一允许使用的页面/状态范围。
6. 基于已批准 PDC、ARC 和清单建立并审批 `AGC-YYYYMMDD-VNN`。分类每个交互区域，映射到共享组件/Token 库，并在页面样式前通过 `AGC-01`–`AGC-06`。`symmetric-navigation` 必须使用等尺寸边缘槽位和相对父级居中的中间子项；不得把多个小动作画成一个大描边按钮。
7. 基于已批准 PDC、ARC、清单和动作组契约建立 `ICON-YYYYMMDD-VNN`，抽取批准页面/状态范围使用的每个 Icon。通过 `IA-01`–`IA-07`：优先复用批准的项目库，映射语义名称/尺寸/风格/状态/来源；每个缺失 Icon 都必须在页面使用前独立设计为可复用、家族风格一致的组件。
8. Figma 读写前加载 `figma:figma-use`。用户要求新建落点时使用 `figma:figma-create-new-file`；否则先验证提供的落点，再修改。
9. 页面 Frame 之前先创建或复用基础：变量/Tokens、语义化文本样式、已批准的动作组和 Icon 组件、其他组件、Variants 和真实资源。只有目标文件缺少必要基础时才加载 `figma:figma-generate-library`；保留已核验的 Code Connect/项目映射作为组件事实来源（`EX-02`），不得创建页面局部控件或 Icon 替代物。
10. 分配 `YYYY-MM-DD-VNN` 设计批次，再在声明的终端外框和尺寸内为所有批准的页面/状态创建完整底层 Frame。使用中性占位；普通内容使用 Auto Layout 和约束；absolute 仅用于已证实的浮层、角标或固定控件。
11. 对整批底层 Frame 执行并记录阻断检查点（`BF-01`–`BF-06`）：页面覆盖、外框契约、根几何、流式层级、状态骨架和评审隔离。所有结果通过或有明确批准例外前，不得添加页面级样式。
12. 只有项目契约、动作组契约、Icon 清单、功能清单、设计基础和底层窗体检查点都通过后，才用 `figma:figma-generate-design` 生成页面；分批叠加共享组件、已核验/待确认产品文案、重要状态和页面级视觉样式。再用 `figma:figma-use` 精修。生成的参考捕获不得作为最终可编辑设计遗留。
13. 每个受影响 Frame 右侧增加独立注释块，产品 Frame 不得写入设计/项目/技术说明，分类 Frame 内每个文字节点，获取完整外框截图，检查节点几何和注释换行边界，并记录验收结果。每次写入后，对所有产品页面/状态 Frame（包括未修改的 Frame）执行共享结构门禁（`G-01`–`G-06`）。返回明确的文件、页面、Frame、组件和状态节点链接。

## Figma 交付规则

- 把 Tokens、组件、Variants、Auto Layout、约束、资源、标注和原型连线视为设计证据；截图本身不足够。
- 每个受影响功能都必须出现在完整容器页面和适用平台壳层中，不得交付裁剪组件。
- 必须先为所有批准的页面/状态构造并验证底层 Frame，再叠加页面级组件和视觉样式；`BF-01`–`BF-06` 未通过时阻断上层工作。
- 必须先根据实际消费项目形成并审批项目设计契约（`PDC-01`–`PDC-06`），再设计整体架构；不能只凭 PRD 或截图。
- 页面级样式前只能使用已批准 `AGC-YYYYMMDD-VNN` 和 `ICON-YYYYMMDD-VNN` 的条目：动作组必须使用声明的组件、宽度/槽位策略、热区尺寸和状态 Token；页面不得用局部 CSS 补偿。16px 用于紧凑/行内 Icon 操作，20px 用于常规控件，24px 用于主导航或 TabBar，32px 用于功能强调或空状态；48px 及以上属于插画/空状态图形，不是普通 Icon Variant。缺失 Icon 必须独立设计为同一资产家族，并把每个实例映射到语义 ID、尺寸、风格、状态和来源。
- 完整页面必须展示声明终端及批准尺寸。小程序设计必须展示适用的小程序视口、设备/状态栏/导航栏/TabBar 外框和安全区行为。
- 注释块按适用情况记录身份、用户/结果、范围、字段/筛选、规则/来源、操作/状态、例外、建议文案、决策和验收证据。
- 反馈改变范围、行为、终端、权限/数据范围、冲突解决或阻塞决策时，重新打开清单门禁。
- 产品 UI 内不得保留交付说明；评审说明放在 Frame 外或 Figma 标注中。
- 产品 Frame 只能包含面向用户的产品 UI 和已验证/待确认产品文案。页面描述、项目解释、技术说明、验收规则和评审意见只能放在右侧独立注释同级块中。
- 不得覆盖约定范围外的已有页面。整体重做交给 `figma-evolve` 的 `regenerate` 模式。
- 不得声称已实现、已高保真或已完成终端验收；这些属于后续 Skill。
- 不得凭提示词、节点创建成功、静态检查或单张看似合理的截图称产物完成，必须遵循共享结构/渲染验收契约。
- 每个页面都记录 G-01 至 G-06：布局责任层、注释配对、文字边界、实例/Master 比例、终端外框高保真和产品内容隔离，或记录已审批例外后，才能称产物完成。
- 第三方设计 lint、Token 或可访问性审计只能作为可选能力。没有用户明确授权及 `EX-03`–`EX-04` 证据时，不得安装、索取 PAT 或声称其结果。

## 问题驱动的设计场景

创建 Frame 前选择适用场景，并把 ID 写入设计契约：

| ID | 给定条件 | 必须形成的 Figma 结果 | 后续证明 |
|---|---|---|---|
| D-01 | 卡片按正常阅读顺序包含标题、动态文案、图片和 CTA。 | 使用嵌套 Auto Layout、间距变量和内容驱动高度；不得把子元素 `x/y` 当作常规布局意图。 | `figma-to-product` 必须用正常流实现，并测试动态文案。 |
| D-02 | 关闭图标、角标或浮动控件覆盖在有边界的卡片上。 | 明确包含它的 Frame 和锚点，并在标注中描述浮层行为。 | `figma-to-product` 仅可在该父级和锚点下使用 absolute。 |
| D-03 | 组件有默认、加载、禁用、空态或错误行为。 | 为 PRD 指定的每个关键状态创建 Variant 或状态 Frame。 | `figma-verify` 必须把每个声明状态加入矩阵。 |
| D-04 | PRD 只指定 `miniapp`、`web` 或一个 App target。 | 设计契约只记录这些 targets。 | 默认不得实现或验收未列出的 target。 |
| D-05 | 页面包含等权导航、TabBar、Tabs 或分段控件。 | 在 Auto Layout/约束中表达声明的分布，并记录子项权重、分区中心点和容差；不得用手工坐标摆放。 | `figma-to-product` 和 `figma-verify` 必须在每个声明 viewport 证明分布正确。 |
| D-06 | 页面包含嵌套卡片、按钮、文字、媒体或共享组件实例。 | 为每个后代保留父子几何契约，并记录有意浮层或溢出例外。 | 验收递归检查所有后代；只检查页面级溢出不能通过。 |
| D-07 | 页面包含上一项/当前或回到当前项/下一项等动作，例如月份导航。 | 登记 `symmetric-navigation`，使用等尺寸边缘热区、相对父级居中的中间动作和紧凑子控件。 | 后续证明记录 `AGC-01`–`AGC-06`、边缘热区相等、中心容差，以及每个声明视口/状态的热区尺寸。 |

这些是可执行假设，不是完成证据。后续实现和验收用例必须先失败，再在修复根因后以截图/运行证据通过。

## 输出契约

返回：

```text
PRD 来源与范围
设计契约和未解决项
项目设计契约修订号、PDC-01 至 PDC-06 结果、推导出的架构修订号（`ARC-YYYYMMDD-VNN`）和证据边界
Icon 资产清单修订号、语义映射、配套资产就绪状态和 `IA-01`–`IA-07` 结果
动作组契约修订号、组件/Token 映射和 `AGC-01`–`AGC-06` 结果
清单版本、功能 ID、审批和冲突结果
设计批次、模块/Frame 组织和注释 ID
Figma 文件链接
新建或更新的页面/Frame/组件/状态节点链接
Tokens 和组件决策
已检查截图
几何、文案分类、可访问性和验收记录
终端外框契约和尺寸
底层 Frame ID、中性截图和 `BF-01`–`BF-06` 检查点结果
所有页面的 `G-01`–`G-06` 写入后门禁结果及已审批例外
页面/状态/转移矩阵和未解决的交互决策
可进入实现的目标终端
未验证边界和下一 Skill
```

## 完成门禁

- 已记录 PRD、设计契约、清单审批、目标文件、终端和物料状态。
- 已检查消费项目并通过 PDC-01 至 PDC-06，或已明确全新项目/`figma-only` 边界和 `Unverified` 字段。
- 已记录由项目设计契约推导出的 `ARC-YYYYMMDD-VNN` 整体架构，且没有未记录的路由、页面族、设计基础、终端、状态或行为。
- 已记录 `AGC-YYYYMMDD-VNN` 动作组契约；页面级样式前 `AGC-01`–`AGC-06` 均已通过，每个获批多动作区域都有组件和布局策略。
- 已记录 `ICON-YYYYMMDD-VNN`，`IA-01` 至 `IA-07` 均已通过，且每个页面 Icon 都映射到已批准的语义家族、尺寸、风格、状态和来源。
- 每个批准页面/状态先通过 BF-01 至 BF-06，再由每个产品页面/状态 Frame 提供 G-01 至 G-06 结果、完整外框截图、文字/可访问性证据和交互决策。
- 缺少集成证明、审批、几何证据或未解决冲突时，不能宣布产物完成。
