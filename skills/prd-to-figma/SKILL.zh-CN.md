# PRD 到 Figma

把 PRD 转为可编辑的 Figma 产物。PRD 是唯一业务事实来源；不得检索知识库、依赖 Lark CLI，或补充没有依据的产品规则。

开始前读取 [`../../knowledge/design-workflow.md`](../../knowledge/design-workflow.md)。它提供共享的最小简报、冲突、变更清单审批、Frame/注释、文案分类和产物验收门禁。

## 必需输入

- PRD 文本、文件或可访问链接。
- Figma 落点：已有文件链接，或用户明确要求新建文件。
- PRD 已声明时的目标终端（`web`、`miniapp`、`app-*`）；`figma-only` 合法。
- 最小简报：目标结果、角色/终端、产品/平台、入口/主流程、范围/排除项和视觉意图。

只有缺失项会改变页面结构、业务行为或交付落点时，才询问那一个缺失项。不得编造终端、角色、权限、流程或未说明状态。

## 工作流

1. 用只读身份/权限证明预检可调用的 Figma 集成。必需集成不可用时停止，不得静默替换其他产物类型。
2. 阅读 PRD，返回认知记录和简洁设计契约：目标、角色、终端、入口和旅程、范围内页面、关键状态、targets、排除项和开放/冲突规则。实质冲突要提供不同解决方案并停止。
3. 创建 `INV-YYYYMMDD-VNN`，包含稳定功能 ID、`Existing — reuse/modify`、`New`、`Conflict` 或 `Unverified` 状态、页面/状态、证据定位和冲突/决策区。Figma 修改前必须获得该清单的明确审批。
4. Figma 读写前加载 `figma:figma-use`。用户要求新建落点时使用 `figma:figma-create-new-file`；否则先验证提供的落点，再修改。
5. 页面 Frame 之前先创建或复用基础：变量/Tokens、语义化文本样式、组件、Variants 和真实资源。只有目标文件缺少必要基础时才加载 `figma:figma-generate-library`。
6. 分配 `YYYY-MM-DD-VNN` 设计批次，再创建完整页面 Frame 及所有关键状态。普通内容使用 Auto Layout 和约束；absolute 仅用于已证实的浮层、角标或固定控件。
7. 只有在契约、已批准清单、落点和基础明确后，才用 `figma:figma-generate-design` 生成页面；再用 `figma:figma-use` 精修。生成的参考捕获不得作为最终可编辑设计遗留。
8. 每个受影响 Frame 右侧增加独立注释块，分类 Frame 内每个文字节点，获取截图，检查节点几何和注释换行边界，并记录验收结果。返回明确的文件、页面、Frame、组件和状态节点链接。

## Figma 交付规则

- 把 Tokens、组件、Variants、Auto Layout、约束、资源、标注和原型连线视为设计证据；截图本身不足够。
- 每个受影响功能都必须出现在完整容器页面和适用平台壳层中，不得交付裁剪组件。
- 注释块按适用情况记录身份、用户/结果、范围、字段/筛选、规则/来源、操作/状态、例外、建议文案、决策和验收证据。
- 反馈改变范围、行为、终端、权限/数据范围、冲突解决或阻塞决策时，重新打开清单门禁。
- 产品 UI 内不得保留交付说明；评审说明放在 Frame 外或 Figma 标注中。
- 不得覆盖约定范围外的已有页面。整体重做交给 `figma-evolve` 的 `regenerate` 模式。
- 不得声称已实现、已高保真或已完成终端验收；这些属于后续 Skill。
- 不得凭提示词、节点创建成功、静态检查或单张看似合理的截图称产物完成，必须遵循共享结构/渲染验收契约。

## 问题驱动的设计场景

创建 Frame 前选择适用场景，并把 ID 写入设计契约：

| ID | 给定条件 | 必须形成的 Figma 结果 | 后续证明 |
|---|---|---|---|
| D-01 | 卡片按正常阅读顺序包含标题、动态文案、图片和 CTA。 | 使用嵌套 Auto Layout、间距变量和内容驱动高度；不得把子元素 `x/y` 当作常规布局意图。 | `figma-to-product` 必须用正常流实现，并测试动态文案。 |
| D-02 | 关闭图标、角标或浮动控件覆盖在有边界的卡片上。 | 明确包含它的 Frame 和锚点，并在标注中描述浮层行为。 | `figma-to-product` 仅可在该父级和锚点下使用 absolute。 |
| D-03 | 组件有默认、加载、禁用、空态或错误行为。 | 为 PRD 指定的每个关键状态创建 Variant 或状态 Frame。 | `figma-verify` 必须把每个声明状态加入矩阵。 |
| D-04 | PRD 只指定 `miniapp`、`web` 或一个 App target。 | 设计契约只记录这些 targets。 | 默认不得实现或验收未列出的 target。 |

这些是可执行假设，不是完成证据。后续实现和验收用例必须先失败，再在修复根因后以截图/运行证据通过。

## 输出契约

返回：

```text
PRD 来源与范围
设计契约和未解决项
清单版本、功能 ID、审批和冲突结果
设计批次、模块/Frame 组织和注释 ID
Figma 文件链接
新建或更新的页面/Frame/组件/状态节点链接
Tokens 和组件决策
已检查截图
几何、文案分类、可访问性和验收记录
可进入实现的目标终端
未验证边界和下一 Skill
```
