# 外部能力选择

当请求可能由官方集成、外部 Skill、参考实现或新的本地 Skill 解决时，加载本参考资料。

## 规则

在提出本地 Skill 前，先检索并评估可信的既有能力。搜索结果、GitHub URL 或关键词命中都不等于可执行能力。

外部能力卡读取 `knowledge/external-capabilities.yaml`，可追溯来源读取 `knowledge/external-sources.yaml`。
`knowledge/skill-index.yaml` 仍只是本地 WTBP Skill 的规范能力卡登记表。

## 每项任务的决策

除路由结论外，还要返回一个采用决策：

| 决策 | 适用条件 | 必要边界 |
|---|---|---|
| `direct-use` | 已可用的官方/客户端能力可覆盖任务，且不需要项目专属的重复流程。 | 在当前上下文核对可用性和权限。 |
| `adapt` | 外部能力有价值，但本地 WTBP Skill 必须施加项目契约、门禁或证据。 | 加载本地 Skill；外部能力不能替代其契约。 |
| `compose` | 两个或以上本地/外部能力负责不同阶段，且没有单一能力拥有完整任务。 | 说明每个阶段的顺序、负责人、边界和证据。 |
| `reference-only` | 来源只适合理解、比较或借鉴结构，不能安全执行任务。 | 不得将它当作项目事实、安装它或声称它已产生结果。 |
| `build-local` | 没有合适能力覆盖一个重复、稳定且项目专属的工作流。 | 先记录检索证据；要求完整本地 Skill 契约、登记关系和 Eval。 |

`manual-optional` 外部能力卡不能因为关键词命中就变成 `direct-use`。它需要用户明确授权，并单独核对来源、固定版本、许可证、权限、凭据和执行环境。不得对能力卡运行 `wtbp install`；该命令只用于另行登记的受控安装路由。

## 决策检查项

推荐直接使用、适配、组合或自建前，比较：

1. 场景匹配：目标、输入、预期输出与非目标。
2. 权威性：发布方、来源 URL、固定版本、许可证、维护状态和信任边界。
3. 副作用：文件、网络、Figma、命令、凭据和安装范围。
4. 证据：该能力能证明什么、哪些仍需项目/运行时/视觉验收，以及未核验项。
5. 复用阈值：项目专属流程是否足够重复和稳定，值得形成带 Eval 的本地 Skill。

缺少任一必要决策输入时，返回 `clarify` 或 `no_match`；不得用静默安装、虚构路由或新建 Skill 来补偿。
